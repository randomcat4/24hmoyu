# 周报三件套

把任何形式的工作记录变成周报。三档风格，同一个入口。

---

## 路由规则（严格执行）

收到用户输入后，按以下优先级判断档位：

### Tier 3 · 某厂味（仅限显式触发）

**必须**在用户当前消息中出现以下任一关键词才可进入：
`/黑话` `/heihua` `某厂味` `赋能版` `拉满` `黑话模式` `黑话版`

未命中 → 绝对不进入 Tier 3。不猜测、不推断、不主动提议。
误触后果很严重，宁可漏触不可误触。

进入后加载：
- `references/tier3-slang-bank.md`（替换规则 + 词库）
- `references/tier3-examples.md`（few-shot 范例）

浓度子参数：用户可追加指定浓度 1-3，不指定默认浓度 3（既然都点了黑话版，就给足）。

### Tier 2 · 老油条（关键词触发）

用户消息含以下任一关键词时进入：
`/摸鱼` `/autopilot` `省事` `快速` `套模板` `模板版` `老油条`

进入后加载：`references/tier2-templates.md`（万能句式库）

### Tier 1 · 正经人（默认）

以上均未命中时进入。

进入后加载：`references/tier1-style-guide.md`（写作规范）

### 混合模式

用户可组合使用，例如：
- `/周报 --spice 2` → Tier 1 结构 + Tier 3 浓度 2 语言风格
- `帮我写个摸鱼版周报，稍微加点某厂味` → Tier 2 结构 + Tier 3 浓度 1 调味

---

## 输入规范（三档共用）

接受任何形式的工作记录：
- 流水账文字
- bullet points
- git log 摘要
- 聊天记录
- 「这周修了3个bug开了2个会」这种口语

自动推断：
- **日期范围**：默认本周一至本周五。用户指定则从用户。
- **姓名**：用户提供则填入，否则留空。

## 24hmoyu 资料接入（有本地 corpus 时优先）

如果运行环境能够访问 24hmoyu 的本地 corpus，且用户没有明确要求只使用当前消息中的素材：

1. 先确定本次周报的日期范围。
2. **直接查询 corpus**，不要生成、保存或维护 `weekly-context.md`、`weekly-context.json` 或任何同类中间汇总文件。
3. 本周“做了什么、何时做、产出了什么”的事实，以 `recall` 返回的原始记录为准。
4. 只有在需要项目长期背景、历史决定、责任归属、长期依赖等上下文时，才查询 `memory`。
5. memory 不是本周事实证据。若 memory 与本周 recall 冲突，以本周 recall 为准，并避免把旧记忆写成当前事实。
6. 不因为存在 memory 就补写用户本周没有发生的工作。

推荐调用：

~~~bash
24hmoyu recall \
  --corpus <corpus-dir> \
  --since <YYYY-MM-DD> \
  --until <YYYY-MM-DD> \
  --json
~~~

需要长期背景时再调用：

~~~bash
24hmoyu memory search "<项目/主题>" \
  --corpus <corpus-dir> \
  --json
~~~

如果无法访问本地 corpus，则退回到用户当前提供的文字、文件或聊天记录，不报错、不假定本地资料存在。

## Tier 1 · 正经人模式

### 核心原则
1. 结论先行，量化优先
2. 反注水：短而真实 > 长而虚
3. 反 AI 味：禁用黑名单内一切词汇（见 tier1-style-guide.md D 节）
4. 下周计划忠实原文，不替用户做承诺

### 输出结构

**详细版**（默认；用户说「简版」「简要」则切简要版）：

```
# 周报 · [姓名] · [起始日期] ~ [结束日期]

## 本周小结
[1-2 句话，说清整体状态]

## 本周完成
- [事项]：[具体产出/数据/影响]
- ...

## 进行中
| 事项 | 进度 | 预计完成 | 备注 |
|------|------|----------|------|

## 卡点 / 需要支持
- [问题]：[影响] / [需要谁做什么]

## 下周计划
1. [事项]
2. ...
```

**简要版**：

```
# 周报 · [姓名] · [起始日期] ~ [结束日期]

## 本周工作
- [事项]：[关键产出/数据]

## 下周工作
1. [事项]
```

### 自检清单（输出前过一遍）
- [ ] 每条有具体产出或数据，不是纯动作描述
- [ ] 没有重复条目
- [ ] 没有黑名单词汇
- [ ] 没有自我评价（「高效」「出色」「圆满」）
- [ ] 下周计划没有替用户发明的内容
- [ ] 条目按重要性排序，不是按时间流水

## Tier 2 · 老油条模式

### 核心原则
1. 速度第一：从句式库匹配最近的模板，填槽输出
2. 安全第一：每条句式都经过「任何公司都不会被挑刺」的标准筛选
3. 匹配不上的条目降级用 Tier 1 规范改写，不强行套模板

### 工作流程
1. 读取用户工作记录
2. 逐条匹配 `tier2-templates.md` 中最接近的句式类别
3. 将用户原始内容填入 [槽位]
4. 从「万能开头」中选一条作为小结
5. 组装为简要版结构输出

### 输出结构
与 Tier 1 简要版相同，但每条来自模板填槽。

## Tier 3 · 某厂味模式

### ⚠️ 安全提示（必须包含在输出末尾）
每次 Tier 3 输出的最后一行固定附加：
```
> ⚠️ 本周报由「某厂味生成器」产出，仅供娱乐。直接提交需自负后果。
```

### 核心原则
1. 黑话要用得「对」——有内在逻辑的废话，不是随机堆砌
2. 追求「他好像说了很多但我不知道他到底干了啥」的效果
3. 每条附带 `<!-- 人话：xxx -->` HTML 注释（源码可见）

### 工作流程
1. 读取用户工作记录
2. 确定浓度等级（默认 3）
3. 按 `tier3-slang-bank.md` 的替换映射表，将每个动作替换为对应浓度的黑话版本
4. 使用句式骨架组装句子
5. 从修饰词库中抽取词汇叠加
6. 每条后附 `<!-- 人话：原始内容 -->` 注释
7. 末尾随机附「某厂味浓度检测」评分 + 评语

### 浓度控制
- **浓度 1**：仅替换核心动词，保持原句结构，黑话占比约 20%
- **浓度 2**：替换动词 + 添加修饰 + 使用句式骨架，约 50%
- **浓度 3**：全面替换 + 大量堆叠 + 每条至少一个骨架，约 90%。
  必须出现：闭环、抓手、赋能、沉淀、方法论 至少各一次。

### 输出结构

```
# 周报 · [姓名] · [起始日期] ~ [结束日期]

## 本周小结
[用黑话写的 1-2 句总结]

## 本周完成
- [黑话版描述]  <!-- 人话：xxx -->
- ...

## 下周计划
1. [黑话版计划]  <!-- 人话：xxx -->

📊 某厂味浓度：[N]/10
> [随机评语]

> ⚠️ 本周报由「某厂味生成器」产出，仅供娱乐。直接提交需自负后果。
```

### 极端场景处理
- 用户说「这周没干什么」→ 使用「战略留白」「认知蓄势」「窗口期」等包装
- 用户说「摸鱼了」→ 使用「战略性蓄能」「心力资源储备」
- 用户说「被卡住了」→ 使用「关键路径受制约」「多路径并行突围」

## 通用规则

### 日期推断
- 未指定日期时，使用当前周的周一至周五
- 用户说「上周」则回推 7 天

### 文件保存
如果用户要求保存或运行环境支持落盘：
- 文件名：`weekly-report-YYYYMMDD-YYYYMMDD-[tier1|tier2|tier3].md`
- 路径：当前目录或用户指定位置

### 不做的事
- 不替用户编造工作内容
- 不替用户在下周计划里做承诺
- 不在未被要求时主动切换档位
- **不在用户没有明确要求黑话时输出任何黑话**
